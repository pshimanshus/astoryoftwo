# A Story Storytelling Hook

## Purpose

Keep story change and continuity active from the first creative response to the
last follow-up. Use the supplied lesson as private craft memory, never as
framework-shaped public copy.

## Load And Ownership

1. Read `references/story-engine.md` for the canonical transformation,
   ERCRT/WHW, carousel-arc, continuity, and repair method.
2. Read `references/source-transcript.txt` only for exact source wording,
   provenance, or reinterpretation.
3. Use `config/skills/creator-skill-stack.md` for session-level channel checks.
4. Use `$a-story-carousel-jam` for concept-to-package production.
5. Let the current creator instruction and `config/rules/` override every
   derived skill or reference.

Do not restate the detailed story engine in this file, the creator stack, the
runtime context, or semantic memory. Those surfaces should invoke it and add
only their own responsibilities.

## Run The Hook

Before the first creative answer and every creative continuation—including
idea thinking, comparison, discussion, rejection, revision, and repair:

1. Refresh the private Story State Card defined in `references/story-engine.md`.
2. Preserve the exact seed, confirmed facts, corrections, and approved concept,
   copy, visual, reference, and format locks.
3. Require a causal `before -> pressure/choice -> after` change row. If nothing
   changes, repair the material before calling it a story.
4. Use ERCRT and WHW privately; never expose their names or unverified
   neuroscience claims in public copy.
5. Make visible action, reaction, object state, gaze, distance, silence, and
   consequence prove the relationship beat.
6. Keep one honest open question alive until the earned turn or payoff.

## Build Or Continue

1. Lock the raw event before universalizing it.
2. Define the cold-viewer recognition mirror.
3. Build distinct receipts that change knowledge, stakes, emotion,
   relationship position, or interpretation on every swipe.
4. Land a fair reframe and one-person send reason.
5. Select one protected architecture from `references/story-engine.md`:
   - default seven-beat: `Cover -> Cold Open -> Mirror -> Spine -> Rhythm ->
     Turn -> Payoff`;
   - reflective six-beat: `Cover -> Cold Open -> Deepening -> Conflict -> Turn
     -> Payoff`.
   Preserve a creator-supplied or approved six-beat structure exactly; do not
   pad, relabel, or force it into seven beats.
6. Treat architecture roles as story phases, not a one-role/one-slide limit.
   Deepening, Conflict, and Turn may each span multiple slides when every added
   scene advances the question, character pressure, visible consequence, or
   answer. Keep at least two causally active characters in a couple story; add
   more only when they materially change the conflict or outcome.
7. Run voice, taste, freshness, DM-send, and format gates after the alive human
   draft exists.

On follow-ups, reopen only the affected layer. Apply the rejection protocol in
`references/story-engine.md`: preserve the creator's exact feedback, mark the
rejected scope superseded, and do not revive or rename it as a fresh route.
Do not erase untouched facts or locks. Run the hook mentally for tiny requests
and answer simply.

## Handoff

Invoke `$a-story-carousel-jam` for full carousel work. After concept lock, use
`$a-story-direct-visual-story` for physical scene direction and copy-hidden
visual checks. This skill owns story continuity; it does not replace identity,
text, format, brandmark, generation, visual-QA, or final-audit gates. Keep this
hook active after handoff until the carousel is completed or explicitly
abandoned.

## Hard Fails

- no meaningful change;
- generic recognition without concrete proof;
- dishonest withholding or an unearned twist;
- public framework or neuroscience language;
- a rejected route returned under a new title without explicit reopening;
- a continuation that forgets a creator correction or approved lock.
