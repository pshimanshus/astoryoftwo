# A Story of Two — website (v2, "the world")

The studio home of **A Story of Two** (Aachu & Zuv) — a multi-room, immersive
long-scroll world you navigate, built on **real first-party Instagram data**. The
hub opens into five rooms, each its own long-scroll; the brand-true paper/
handwriting/illustration language and a hand-set room index hold them together.

Design spec:
[`docs/superpowers/specs/2026-06-15-astory-website-v2-design.md`](../docs/superpowers/specs/2026-06-15-astory-website-v2-design.md).

## Pages

```
site/
  index.html     # the hub — immersive entry (brand assembles), proof whisper,
                 #   the soul beat, a glimpse reel, the doorway "map", reach-out
  reels.html     # 01 The Reels   — 69 real covers + real view counts, sortable wall
  stories.html   # 02 The Stories — swipeable carousel + cover grid + illustrations
  memory.html    # 03 The Memory  — scrapbook album of real photos
  studio.html    # 04 The Studio  — the universe + coming-soon surfaces
  brands.html    # 05 For Brands  — proof-as-story, format range, rituals, #reach
  styles.css     # the design system (warm paper editorial + the world components)
  main.js        # reveals, nav, swipeable carousel, count-up, reel-wall sorting
  data/feed.json # the canonical real feed (numbers + cover paths) the pages read
  assets/        # reels/real (69 covers), carousels, memory, art, photos
```

## Run locally

Static — no build step to *view* it.

```bash
cd site
python3 -m http.server 8753
# open http://localhost:8753
```

## The data pipeline (real, first-party)

Numbers and covers come from the owned account via the Instagram Graph API
(Apify was over its monthly hard limit; first-party data is better anyway). To
refresh after new posts:

```bash
# 1) pull the full account inventory + per-post insights → data/instagram/
python3 scripts/instagram_pull_account.py            # needs INSTAGRAM_ACCESS_TOKEN in .env.local

# 2) merge insights + download reel covers → site/data/feed.json + assets/reels/real/
python3 scripts/build_site_feed.py

# 3) regenerate the data-driven room pages from the feed
python3 scripts/build_pages.py
```

`index.html` is hand-authored; `reels/stories/memory/studio/brands.html` are
generated by `scripts/build_pages.py` (shared nav/footer live there, so the
whole site stays consistent). The deployed site is fully static — the scripts
are a one-time authoring step that bakes real numbers into HTML.

## Deploy

Drag `site/` onto **Netlify Drop**, or point **Vercel / Cloudflare Pages /
GitHub Pages** at it. No config.

## Lighting up a coming-soon surface (podcast / YouTube / shop / app)

In `scripts/build_pages.py` → `build_studio()`, change that surface's card from a
`<div class="uni uni--soon">` to an `<a class="uni uni--live" href="…">`, swap
`Coming soon` → `Live` and `Soon` → the action (`Listen ↗`, `Watch ↗`,
`Shop ↗`), then re-run `python3 scripts/build_pages.py`. To embed real media,
drop a responsive 16:9 iframe (YouTube `youtube.com/embed/<id>`, Spotify
`open.spotify.com/embed/show/<id>`) into the room. The live/soon styling is
class-driven — no other changes needed.

## Reach-out

`a.storyof.two.collab@gmail.com`. Structured so a real captured form and a
store/app "notify me" waitlist can drop in later without redesign.

## Asset provenance

Reel covers are first-party `thumbnail_url` frames; carousel slides from
`.carousel_research/`; memory photos from `references/identity` + `places`;
illustrations from the house style. All local copies (resized with `sips`) — no
Instagram CDN hot-linking (those URLs expire).
