# Plan for preventing recurring AI image defects

Date: 2026-09-30. Status: researched proposal; skill and runtime changes are not implemented.

The proposed `non-ai-image-skill` should make A Story of Two images physically coherent, recognizable, intentional, and faithful to the approved scene and watercolor direction. The creator clarified that this means preventing the AI-generated look and recurring defects, while continuing to use AI generation.

The strongest pattern is incorrect relationships between otherwise plausible elements: a screen on a phone's rear face, a hand touching the wrong body region, a person merging into a doorway, or a sealed parcel becoming opened without a story transition. A longer list of style adjectives will not address these failures. The recommendation is a compact skill connected to scene-specific planning, independent pixel inspection, existing release gates, and a regression collection of rejected and accepted images.

No skill can guarantee that a probabilistic generator never produces another defect. The operational target is to prevent avoidable errors before generation, detect and contain known defects before creator review or release, and measure missed defects honestly. Passing the proposed checks would establish their measured coverage, not universal visual correctness or creator approval.

## Why existing checks have not been enough

The repository already checks hashes, dimensions, palette, references, planned hand inventories, review completeness, quarantine, and approval sequencing. Preserve these controls. The main distinction is stated in [carousel_pixel_qa.py](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:1): it validates authored observations and does not itself perform vision.

Static inspection found the following limits; these are code observations, not demonstrated live bypasses:

- Physical action/relationship evidence can satisfy the validator with PASS plus eight characters. [Implementation](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:222).
- `generic_ai_tells: []` declares that none were observed; it does not detect them. [Implementation](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:429).
- Hands are matched by owner/side, while contact text is not structurally compared with the planned action and target region. Story-carrier names match, but their actual states are not compared structurally. [Hands](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:547), [carriers](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:450).
- Adult scale, support, and accessory side lack equivalent mandatory structured observations. New lettering inventory remains optional for compatibility with historical records. [Silhouette](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:580), [lettering](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_pixel_qa.py:666).
- Generic hand-map fallbacks can replace intentional blocking; chronology logic covers a narrow set of phrases. [Fallback](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_visual_integrity.py:67), [chronology](/Users/himanshusharma/astoryoftwo-analysis/pipeline/stages/carousel_visual_integrity.py:413).
- Some feedback evaluations validate `slides.json`, which establishes plan conformance rather than repaired pixels. Corrections need separate planned, rendered, inspected, and creator-approved states.

Existing unit tests include solid-fill image fixtures with authored observations. They test validation logic, not visual recognition. [Fixture explanation](/Users/himanshusharma/astoryoftwo-analysis/tests/helpers/carousel_qa.py:29). The [recorded active-style smoke rollout](/Users/himanshusharma/astoryoftwo-analysis/config/evals/carousel-live-smoke-report.json:6) is BLOCKED after extra hands/wrong contact and undersized Reel output; it reports zero false promotions and zero creator approvals. Its older top-level PASS is explicitly historical. This demonstrates useful rejection controls, not reliable current generation.

The taxonomy also points to a `references/failures/visual-inconsistencies/` directory that was not found in this checkout. A negative-reference instruction cannot operate reliably if its assets cannot be resolved. Use actual existing paths and content hashes.

## Proposed skill design

Proposed location: `.agents/skills/non-ai-image-skill/SKILL.md`. Keep it specific to A Story of Two production so its identity/style rules do not leak into unrelated image tasks. Activate for locked-scene planning, image review, visual repair, and “looks AI-generated” complaints. Hand open-ended concepts back to carousel-jam. The skill does not determine whether an image was made by AI.

The entrypoint should be short. It should route to canonical rules, an issue-to-control reference, and a hash-bound example manifest rather than restating every rule. Integrate it through the existing carousel-jam/direct-visual-story workflow and skill-system registry. Keep current failure codes; add narrowly scoped subtypes such as `phone_face_orientation` under `SCENE_LOGIC_CONTRADICTION` instead of inventing a parallel taxonomy.

Proposed supporting resources:

- `references/issue-controls.md`: when each check applies, observable rejection condition, accepted counterexample, and repair strategy.
- `references/regression-manifest.json`: references to reviewed original assets, hashes, precise labels, source corrections, and approval scope. Do not duplicate the private identity library or large image archive.
- A small review-bundle helper only if existing tooling cannot reliably resolve originals, calculate hashes/dimensions, and present full-frame plus selected details. Such a helper prepares evidence; it cannot certify anatomy or taste.

### The production procedure

1. **Resolve the actual correction.** Preserve exact words, affected slide/asset, scope, and supersession. Separate the observed defect from a suspected cause. “The phone is impossible” must not become an unrelated global style policy. Follow package-specific correction links before derived learning summaries.
2. **Define the physical scene.** Lock actor, action, target, consequence, temporal phase, camera side, support planes, visible hands, key object states, and intended eye-lines. Add prop-face/orientation facts only for relevant objects. Reject inconsistent plans before generation.
3. **Carry continuity and identity.** Reuse actual identity references and the active style board; maintain incident-level clothes, accessories, geography, and prop state. Record allowed changes between slides.
4. **Select applicable risk checks.** A phone activates orientation/use checks; a doorway activates threshold/body-boundary checks; touching activates limb ownership and contact; a continuous incident activates sequence checks. Keep exact copy, dimensions, signature, identity, and style as baseline checks. Avoid loading every historical incident into every prompt.
5. **Compile and prove the riskiest scene.** Keep the current 8,000-character/1,050-word prompt caps and exact locked content. Use explicit positive geometry and selective negative constraints. Verify required contracts survive compilation. Preserve one physical event per slide and two-to-four story-evidence carriers.
6. **Inspect what was actually rendered.** In quarantine, open the exact file. First describe the visible event without the intended answer; then compare with the scene contract. Use full frame, relevant contact/object details, and a phone-size view. For image-first story reading, ignore on-image copy initially; record any unavoidable textual influence. Never infer pixels from prompt text or a filename.
7. **Use two focused review responsibilities.** One independent reviewer checks physics, entities, identity, and continuity; another checks scene meaning, copy relation, medium, and finish. Reuse existing independence machinery where possible. Reviewer disagreement or unclear critical evidence remains blocked; voting cannot erase a specific defect. Independence of assignment does not guarantee independent model errors.
8. **Repair by cause and preserve invariants.** A local object defect can receive a local edit when the scene works; rerun full-frame and dependent checks after it. Wrong action requires new staging. Wrong story requires premise repair. A new hash invalidates prior review. Do not force whole-deck regeneration for one failed slide.
9. **Inspect the sequence and release through existing gates.** Compare adjacent slides and the contact sheet for identity, wardrobe, props, geography, action, and payoff. Keep technical QA, creator proof approval, final audit, and publishable state separate. Never use an average score to override a critical defect.

Before implementation, reconcile pose scope against [identity.md](/Users/himanshusharma/astoryoftwo-analysis/config/rules/identity.md:178), which explicitly prohibits crouched/squatting poses. Use the approved style examples and original creator corrections to define the boundary; the proposed skill cannot silently override that authority. Accepted style alone does not approve an otherwise prohibited pose. Also keep object-specific checks consistent with the current [phone integrity rule](/Users/himanshusharma/astoryoftwo-analysis/config/rules/scene-entity-integrity.md:138); this plan creates no new exception for a different device design.

Current instructions disagree on retry limits: the direct-visual skill says two misses trigger premise repair, while the scene-integrity rule describes initial attempt plus two repairs. Resolve this against the current runtime before implementation. The recommended contract is the current runtime's two attempts for one premise, followed by redesign, plus an episode-level generation ledger that survives semantic revisions. A revised premise must not erase cost/history or silently start endless retries. Planning does not authorize additional generation calls.

## Regression cases and measurement

Start with actual existing rejected images rather than newly invented labels. Maintain separate calibration and held-out cases; no image or repair sibling should leak between those sets. Have the creator adjudicate genuinely disputed taste labels during normal review. Existing approved examples can establish their documented scope immediately; approval of a style board is not approval of every depicted physical detail.

Required cases include: screen plus rear cameras on one face; correct hand count with wrong target; merged body/object boundary; compressed scale; wrong threshold/unsupported parcel; identity drift; accessory on wrong side; unexplained wardrobe/parcel-state change; wrong gaze or gesture; socks/pants chronology contradiction; attractive but unreadable sofa joke; purposeless scene repetition; yellow/generic finish; and exact copy plus extra incidental lettering. Cover every family from the issue table, recording missing fixtures instead of claiming complete coverage.

After phase 1 resolves rule scope, counterexamples must include natural occlusion, a motivated pose permitted by the reconciled rules, a coherent phone front or rear, a hidden accessory, approved painterly edges, repeated framing with meaningful state change, and a justified wardrobe change. These prevent the skill from rejecting good art through overbroad rules. Test formats independently only when those formats were requested; one 3:4 review cannot approve different 9:16 pixels.

Track these separately, by family and configuration version:

- **Known-defect miss rate:** rejected labeled cases the reviewer passes / rejected labeled cases reviewed.
- **False-rejection rate:** accepted labeled cases the reviewer blocks / accepted labeled cases reviewed.
- **Review coverage:** inspected current slide-format assets / required assets; list missing families and unresolved observations.
- **Generation quality:** first-attempt acceptance, repair attempts, and repeated defect classes per distinct generated asset.
- **Release quality:** creator rejection after technical PASS, critical escapes, stale-asset promotions, and unapproved promotions.
- **Cost:** generation calls and reviewer time/tokens per accepted image and sequence.

For the initial finite regression set, require zero known critical false passes and zero false failures on the designated counterexamples. Report the actual sample size and uncertainty; zero observed misses does not establish a zero future miss rate. Hold existing palette and prompt thresholds fixed. Rerun the frozen regression collection after generator, reviewer, prompt, reference, or rule changes. Once held-out failures inform a repair, move those cases into the regression collection; reserve fresh unseen cases for the next independent validation. Do not describe repeatedly tuned-on images as held out. If fresh cases are unavailable, report regression-only confidence rather than extending the generalization claim.

The skill is complete only when its routing works, the runtime checks enforce the intended transitions, independent image review passes the declared fixture coverage, and the production pilot is reported. A Markdown skill, a complete QA JSON, or passing contract tests alone does not meet that completion condition.
